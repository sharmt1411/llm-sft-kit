# Standard Schemas & Archival Templates

## 0. 标准项目文件树结构

```text
project/
├── configs/                          # 手写配置（进 git）
│   ├── base.yaml                     # 公共设置（模型、数据权重、基础超参）
│   ├── exp_0001_smoke_test.yaml      # 只写与 base 不同的部分，带四位序号方便排序
│   └── exp_0002_baseline.yaml
│
├── data/                             # 大文件不进 git
│   ├── raw/                          # 原始数据，只读
│   ├── processed/
│   │   ├── v1/
│   │   │   ├── train.jsonl
│   │   │   ├── val.jsonl
│   │   │   └── manifest.json         # 来源、样本数、sha256、清洗规则、变更说明
│   │   └── v2/
│   └── eval/                         # 评测集，同样版本化，跨实验恒定
│       └── v1/
│
├── scripts/                          # 进 git
│   ├── prepare_data.py               # raw -> processed/vN
│   ├── train.py                      # 合并配置、生成 config.yaml 和 meta.json
│   └── deploy_serving.py             # 部署 OpenAI 兼容 SSE 推理接口
│
├── runs/                             # 每次训练一个目录
│   └── YYYY-MM-DD_exp_XXXX_desc/
│       ├── config.yaml               # 自动生成：base + exp 合并后的完整配置快照
│       ├── meta.json                 # 自动生成：git commit、数据 sha256、库版本、GPU、起止时间
│       ├── logs/
│       │   ├── train.log             # 终端输出文本（DualLogger 双写）
│       │   └── tensorboard/          # 曲线事件文件
│       ├── checkpoints/
│       │   ├── best/                 # 最优 LoRA adapter
│       │   └── last/                 # 末步 LoRA adapter
│       ├── eval_results.json         # 评测结果与训练指标
│       ├── NOTES.md                  # 手写复盘：假设、结果、结论、问题、下一步
│       └── evidence/                 # 可选：异常曲线截图、问题样本索引
│
├── experiments.md                    # 【手写】：实验总表，一行一个实验
├── lessons.md                        # 【手写】：跨实验沉淀的规律和踩坑
├── uv.lock                           # 依赖锁定（或 requirements.txt）
└── .gitignore                        # 忽略 data/、runs/*/checkpoints/ 等大文件
```

## 1. Single-Run `NOTES.md` Template

```markdown
# exp0002_lr1.5e-4_r32

## 假设
将学习率设为 1.5e-4、LoRA rank=32，预期验证集 loss 稳定收敛至 0.5 以下。

## 结果
- 训练耗时: 42.5 分钟
- 最终 `val_loss`: 0.4983 (best 0.4921 @ epoch 2.95)
- 平台评测指标: (若已接 eval-platform 则填写通过率 / 分歧摘要)

## 结论
有效，验证集拐点出现在第 3 轮，第 4-5 轮轻微过拟合，已通过 `load_best_model_at_end` 锚定最优权重。

## 问题 / 异常
验证集 500+ 条时 `eval_steps=50` 耗时偏高，后续可调大至 100-150。

## 下一步
将服务部署到推理端点并使用 `evalctl` 做基座/微调对比评测。
```

## 2. `experiments.md` Table Format

```markdown
| ID | 改动点 | 数据版本 | 训练/评测指标 | 推理性能 (TTFT / TPOT / TPS) | 结论 | 是否保留模型 |
|---|---|---|---|---|---|---|
| exp0001 | 2-step 全链路冒烟验证 | v1 | val_loss=1.70 | - | 全链路跑通 | 否 |
```

## 3. `manifest.json` (Generated by `prepare_data.py`)

Records `version`, `created_at`, `seed`, `val_ratio`, `enable_thinking`, `expand_multiturn`, `summary`, per-file `sources` (`sha256`, `raw_lines`, `valid_samples`, `weight`, `train_distinct`, `train_weighted`, `val_distinct`), `cleaning_rules`, and output `files` SHA256 hashes.
